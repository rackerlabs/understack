### Deploy repo changes

Skyline's `Database`, `User` and `Grant` resources are now rendered by the chart, with a `Connection` that writes `skyline-db-conn`, instead of coming from `components/skyline/skyline-mariadb-db.yaml`, which is removed.

Skyline reads its database settings from its own config rather than from oslo.config, so it still takes the password from `endpoints.oslo_db.auth.skyline.password`. That value must stay in your deploy repo and must match the `password` in the `skyline-db-password` Secret.

The `skyline-db-password` Secret (`username` and `password` keys) is still read from your deploy repo, and the chart no longer renders it, so it must exist before this change syncs.

Argo CD prunes the old `Grant` named `skyline-grant`; the chart's is named `skyline`. Check that all of them are Ready after the sync:

```bash
kubectl -n openstack get database,user,grant,connection -l application=skyline
```

The old `skyline-grant` can get stuck terminating. With `privileges: [ALL]` and `grantOption: true`, the operator's finalizer fails on delete with ``Error 1064 ... near 'ON `skyline`.* FROM 'skyline'@'%''`` (seen on mariadb-operator 25.8.4). If `skyline-grant` is still present with a `deletionTimestamp`, revoke the privileges by hand and then remove the finalizer so the object can go away:

```bash
kubectl mariadb -n openstack mariadb -e "REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'skyline'@'%';"
kubectl -n openstack patch grant skyline-grant --type=merge -p '{"metadata":{"finalizers":null}}'
```

Patching the finalizer alone leaves the old grant in the database. The new `skyline` Grant re-applies the privileges for the same account.
