### Deploy repo changes

Ironic now gets its `[database] connection` from the MariaDB operator instead of from the `IRONIC_DB_PASSWORD` Helm value. The chart renders the `Database`, `User`, `Grant` and `Connection` resources, and the operator writes the connection string into the `ironic-db-conn` Secret, which is projected into the API, conductor, novncproxy and db-sync workloads. `components/ironic/ironic-mariadb-db.yaml` is removed.

The `ironic-db-password` Secret (`username` and `password` keys) is still read from your deploy repo, and the chart no longer renders it, so it must exist before this change syncs. Pods wait for `ironic-db-conn`, so a missing Secret shows up as pods stuck in `ContainerCreating`.

Argo CD prunes the old `Grant` named `ironic-grant`; the chart's is named `ironic`. Check that both are Ready after the sync:

```bash
kubectl -n openstack get database,user,grant,connection -l application=ironic
```

The old `ironic-grant` can get stuck terminating. With `privileges: [ALL]` and `grantOption: true`, the operator's finalizer fails on delete with ``Error 1064 ... near 'ON `ironic`.* FROM 'ironic'@'%'' `` (seen on mariadb-operator 25.8.4). If `ironic-grant` is still present with a `deletionTimestamp`, revoke the privileges by hand and then remove the finalizer so the object can go away:

```bash
kubectl mariadb -n openstack mariadb -e "REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'ironic'@'%';"
kubectl -n openstack patch grant ironic-grant --type=merge -p '{"metadata":{"finalizers":null}}'
```

Patching the finalizer alone leaves the old grant in the database. The new `ironic` Grant re-applies the privileges for the same account.

`IRONIC_DB_PASSWORD` in `secret-openstack.yaml` is no longer used and can be removed from your deploy repo once every cluster is on this version.
