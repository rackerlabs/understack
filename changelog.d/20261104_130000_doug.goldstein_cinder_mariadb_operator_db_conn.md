### Deploy repo changes

Cinder now gets its `[database] connection` from the MariaDB operator instead of from the `CINDER_DB_PASSWORD` Helm value. The chart renders the `Database`, `User`, `Grant` and `Connection` resources, and the operator writes the connection string into the `cinder-db-conn` Secret, which is projected into every Cinder workload that talks to the database. `components/cinder/cinder-mariadb-db.yaml` is removed.

The `cinder-db-password` Secret (`username` and `password` keys) is still read from your deploy repo, and the chart no longer renders it, so it must exist before this change syncs. Pods wait for `cinder-db-conn`, so a missing Secret shows up as pods stuck in `ContainerCreating`.

Argo CD prunes the old `Grant` named `cinder-grant`; the chart's is named `cinder`. Check that both are Ready after the sync:

```bash
kubectl -n openstack get database,user,grant,connection -l application=cinder
```

The old `cinder-grant` can get stuck terminating. With `privileges: [ALL]` and `grantOption: true`, the operator's finalizer fails on delete with ``Error 1064 ... near 'ON `cinder`.* FROM 'cinder'@'%'' `` (seen on mariadb-operator 25.8.4). If `cinder-grant` is still present with a `deletionTimestamp`, revoke the privileges by hand and then remove the finalizer so the object can go away:

```bash
kubectl mariadb -n openstack mariadb -e "REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'cinder'@'%';"
kubectl -n openstack patch grant cinder-grant --type=merge -p '{"metadata":{"finalizers":null}}'
```

Patching the finalizer alone leaves the old grant in the database. The new `cinder` Grant re-applies the privileges for the same account.

`CINDER_DB_PASSWORD` in `secret-openstack.yaml` is no longer used and can be removed from your deploy repo once every cluster is on this version.
