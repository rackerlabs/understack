### Deploy repo changes

Horizon's `Database`, `User` and `Grant` resources are now rendered by the chart, with a `Connection` that writes `horizon-db-conn`, instead of coming from `components/horizon/horizon-mariadb-db.yaml`, which is removed.

Unlike the other services, Horizon is a Django application and not an oslo.config service. Its settings still read the database password from `endpoints.oslo_db.auth.horizon.password`, so `HORIZON_DB_PASSWORD` must stay in `secret-openstack.yaml` and must match the `password` in the `horizon-db-password` Secret.

The `horizon-db-password` Secret (`username` and `password` keys) is still read from your deploy repo, and the chart no longer renders it, so it must exist before this change syncs.

Argo CD prunes the old `Grant` named `horizon-grant`; the chart's is named `horizon`. Check that both are Ready after the sync:

```bash
kubectl -n openstack get database,user,grant,connection -l application=horizon
```

The old `horizon-grant` can get stuck terminating. With `privileges: [ALL]` and `grantOption: true`, the operator's finalizer fails on delete with ``Error 1064 ... near 'ON `horizon`.* FROM 'horizon'@'%'' `` (seen on mariadb-operator 25.8.4). If `horizon-grant` is still present with a `deletionTimestamp`, revoke the privileges by hand and then remove the finalizer so the object can go away:

```bash
kubectl mariadb -n openstack mariadb -e "REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'horizon'@'%';"
kubectl -n openstack patch grant horizon-grant --type=merge -p '{"metadata":{"finalizers":null}}'
```

Patching the finalizer alone leaves the old grant in the database. The new `horizon` Grant re-applies the privileges for the same account.
